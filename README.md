# Boxes

Website for Boxes, a fictional UK online packaging shop, on the agency WordPress platform
(Cloud Run). WordPress core, wp-config, mu-plugins (yacf, GCS uploads) and the APCu object
cache live in the `wp-base` image; this repo owns only what is unique to the client.

## What you own

| Path | Purpose |
| --- | --- |
| `content/catalogue.json` | Product, category and collection catalogue; the single source for the static build and the seed |
| `static/` | Verified static HTML/CSS prototype generated by `tools/build.mjs`; the source the theme is ported from |
| `tools/` | The static site generator |
| `wp-content/themes/` | The `boxes` theme |
| `wp-content/plugins/` | Client plugins (rarely needed) |
| `wp-content/yacf/` | Content model: post types, taxonomies, fields, options pages (YAML) |
| `wp-content/seed/` | `seed.php` (idempotent content seed) + its images. `run.php` is the platform's bootstrap runner, never edit it |
| `Dockerfile` | Copies `wp-content` and the catalogue, bundles the theme CSS, runs `wp-build`. Bump the `wp-base` tag to take platform updates |
| `firebase.json` | Firebase Hosting rewrite for `boxes.junaid.guru` (site `boxes-junaid`) |

## Static prototype

`static/` is generated, then served as plain files. Every page, string and image there is
final; the WordPress theme and seed reproduce it 1:1.

```bash
node tools/build.mjs
python3 -m http.server 8790 --directory static
```

Then open http://localhost:8790.

## Local development

Open in the devcontainer. It builds the image, starts MariaDB, installs WordPress
(admin / password), builds the yacf model, copies `content/catalogue.json` to
`wp-content/seed/catalogue.json` and runs `wp-content/seed/run.php`.
Site: http://localhost:8083, database on host port 3309.

The devcontainer mounts your `wp-content` dirs into the running image and enables
OPcache timestamp validation, so edits apply on refresh.

If a container comes up "healthy" but WordPress cannot reach the database ("Error
establishing a database connection"), it likely lost its network attachment (a known
Docker Desktop flake after repeated `down`/`up` cycles): `docker inspect <container>
--format '{{len .NetworkSettings.Networks}}'` shows `0`. Fix:
`docker network connect --alias db <project>_default <db-container>` then
`docker network connect <project>_default <app-container>`.

## Onboarding checklist

1. firebase-cloud, branch `feat/boxes`: `terraform/apps/boxes.tf`, the catalog entry in
   `apps/mysql-catalog.tf` and the outputs in `apps/outputs.tf` and the root `outputs.tf`.
   Run `terraform apply` (the first apply is expected to fail creating the Cloud Run
   service because the DB secret versions do not exist yet).
2. personal-cloud: `gh workflow run terraform-mysql-apps.yaml --repo poly-glot/personal-cloud --ref main`
   to provision the database and secret versions, then re-run `terraform apply`. If it
   409s ("already exists"), `terraform import` the service instead of recreating it.
3. `gh secret set WIF_PROVIDER -R poly-glot/boxes --body "$(terraform output -raw boxes_wif_provider)"`
   and the same for `GCP_SA_EMAIL` from `boxes_gcp_sa_email`.
4. Admin password:
   `openssl rand -base64 30 | tr -d '/+=' | cut -c1-24 | tr -d '\n' | gcloud secrets create boxes-wp-admin-pass --project firebase-cloud-491613 --replication-policy=automatic --data-file=-`
5. Push to `main`. The deploy workflow builds, deploys Cloud Run service `boxes`, runs
   the bootstrap job and deploys Firebase Hosting.
6. Create the bootstrap job once (the production image has no wp-cli; `run.php` installs
   WordPress and runs the seed):
   ```bash
   gcloud run jobs create boxes-bootstrap --project firebase-cloud-491613 --region europe-west2 \
     --image europe-west2-docker.pkg.dev/firebase-cloud-491613/firebase-cloud/boxes:<tag> \
     --command php --args /app/public/wp-content/seed/run.php \
     --service-account boxes-runtime@firebase-cloud-491613.iam.gserviceaccount.com \
     --set-secrets DB_HOST=db-host:latest,DB_USER=boxes-db-user:latest,DB_PASS=boxes-db-pass:latest,DB_NAME=boxes-db-name:latest,WP_ADMIN_PASS=boxes-wp-admin-pass:latest \
     --set-env-vars DB_SSL=1,WP_TITLE=Boxes,GCS_UPLOADS_BUCKET=<bucket> \
     --max-retries 0 --task-timeout 600
   gcloud run jobs execute boxes-bootstrap --project firebase-cloud-491613 --region europe-west2 --wait
   ```
   CI updates and re-executes the job on every push.
7. DNS: add the record from `terraform output boxes_required_dns`
   (usually `CNAME boxes -> boxes-junaid.web.app` for `boxes.junaid.guru`).

## Production

Pushes to `main` deploy to Cloud Run (service `boxes`) in `firebase-cloud-491613` /
`europe-west2`, then re-run the bootstrap job so content model and seed changes land.
Firebase Hosting serves `boxes.junaid.guru` by rewriting `**` to the service and
forwarding only the `__session` cookie: the public site works, but wp-admin stays on the
run.app URL. Media uploads go to the app's GCS bucket via the runtime service account.
wp-cron runs from Cloud Scheduler; file mods are disabled on Cloud Run.
